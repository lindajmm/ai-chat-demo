1. builder 接收接口 Class，保存传入的 `chatModel`、记忆工厂等配置；
2. build () → JDK 动态代理生成 `Assistant` 的代理实例；
3. 调用 `assistant.chat(xxx)` 时，代理的 InvocationHandler 执行：
   - 根据 memoryId 拿到独立 ChatMemory
   - 取出历史消息 + 当前用户消息拼成消息列表
   - 调用**绑定好的 chatModel.chat (messages)** 访问大模型
   - 把 AI 回复存入记忆，返回结果

>
> 重点区分：
>
>
> - `ChatModel`：底层，只负责发请求给大模型，输入是`List<ChatMessage>`，无记忆；
> - `AiServices`：高层编排器，不直接和大模型通信，**负责包装、调度、管理记忆 / 提示词 / 工具，最后调用 ChatModel**。

## 补充两个容易混淆的点

1. AiServices 本身**不是 Spring Bean**，它只是一个工厂类；你是用它生成代理对象，再把代理对象注册成 Spring 的 @Bean（也就是你代码里的 Assistant Bean）。
2. 新版本 langchain4j 还提供 `@AiService` 注解，不用手动写 @Bean + AiServices.builder，starter 自动扫描接口生成 Bean，是简化写法，底层依然是 AiServices。

## 面试背诵版

>
> AiServices 是 LangChain4j 的高层代理工厂，基于 JDK 动态代理，给自定义接口生成实现；它负责消息封装、对话记忆管理、系统提示词、工具编排，内部调用 ChatModel；目的是把 LLM 调用声明式化，减少样板代码。
